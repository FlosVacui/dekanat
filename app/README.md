# Деканат в кармане: приложение

Концепт личного кабинета студента для конкурса. Все данные вымышленные. Это не официальный сервис вуза.
Стек и устройство — [ADR-0001](../docs/adr/ADR-0001-stack.md). Команды ниже запускаются из папки `app/`.

## Что нужно на чистой машине
Ничего не ставится «в систему» автоматически: пункты 1 и 2 вы готовите сами.

1. Node.js 24 или новее (`node -v`) и npm.
2. PostgreSQL 18, запущенный на `127.0.0.1:5432`. Скрипт подготовки входит в него как суперпользователь `postgres` без пароля, поэтому с вашей машины вход под `postgres` должен быть разрешён. Docker для локальной работы не нужен.
   - Проверка: `pg_isready -h 127.0.0.1 -p 5432`.
   - Другой адрес или порт — переменные окружения `PGHOST`, `PGPORT`, `PGSUPERUSER` при запуске `npm run db:setup`.
3. Git. Склонируйте репозиторий и перейдите в `app/`.

## С нуля, по шагам
```
npm ci                      # зависимости строго по package-lock.json
npm run db:setup            # роли dekanat_owner и dekanat_app, базы dekanat и dekanat_test, файл .env в корне репозитория
npm run db:migrate          # схема базы из app/db/migrations/
npm run db:seed             # вымышленные данные: два студента и сотрудник
npm run playwright:install  # браузер Chromium для сквозного теста, в кэш пользователя (нужен один раз)
npm run build               # рабочая сборка
npm run start -- -p 3000    # приложение на http://localhost:3000
```
- `db:setup` создаёт `.env` в **корне репозитория** со случайными паролями и ничего не печатает. Файл один: в `app/` файлов `.env*` нет. Он в `.gitignore`. Если файл уже есть, скрипт его не перезаписывает.
- `db:seed` можно запускать повторно. Расписание строится от сегодняшнего дня на семь дней вперёд: **перед сквозным тестом и снимками запускайте `db:seed` заново**, иначе пар на сегодня может не быть. **Он возвращает основной набор в исходное состояние:** заявки, история статусов и уведомления аккаунтов основного набора, которых нет в вымышленных данных, удаляются. Данные других наборов он не трогает.
- Логины основного набора: студенты `belozerov` и `nesterova`, сотрудник `dekanat`. Пароли выдаёт команда проекта; в README они не пишутся.
- Для разработки вместо `build` и `start`: `npm run dev`.

## Команды
| Команда | Что делает |
|---|---|
| `npm run typecheck` | Проверка типов TypeScript |
| `npm run lint` | Линтер ESLint; он же следит, чтобы клиент базы был только в `src/server/dal/`, а `process.env` — только в `src/server/config.ts` |
| `npm test` | Модульные тесты Vitest на отдельной базе `dekanat_test` (рабочая база не затрагивается) |
| `npm run check` | Типы, линтер и модульные тесты подряд |
| `npm run test:e2e` | `db:seed`, сборка и сквозной тест Playwright на экране 360×800 |
| `npm run test:e2e:run` | Только сквозной тест: приложение уже собрано, данные уже посеяны |
| `npm run screenshots` | `db:seed`, сборка и снимки каждого экрана на 360 и 1280 px в `docs/evidence/screenshots/<дата>-2.4/` |
| `npm run db:setup` | Роли, базы и `.env` (один раз) |
| `npm run db:generate` | Новый файл миграции из схемы `src/server/dal/schema.ts` |
| `npm run db:migrate` | Применить миграции |
| `npm run db:seed` | Вставить вымышленные данные основного набора |
| `npm run build` / `npm run start` / `npm run dev` | Сборка, запуск собранного приложения, режим разработки |

Все команды, которым нужны переменные окружения, получают файл `.env` из корня репозитория через `scripts/with-env.mjs`.

## Сквозной тест
- Файл: `tests/e2e/m0.spec.ts`. Десять шагов раздела 7 [сценариев](../docs/design/S-2.1-scenarios.md) идут по порядку; каждое касание — отдельный шаг.
- Тест сам запускает собранное приложение на порту 3100 (`E2E_PORT` меняет порт) и между шагами 7 и 8 перезапускает его: процесс останавливается и запускается заново, база не стирается. Порт должен быть свободен.
- Тест проверяет и куку `__Host-session` с флагом `Secure` на `http://localhost` в Chromium.
- Тест создаёт заявку в рабочей базе `dekanat`. Команды `test:e2e` и `screenshots` начинают с `db:seed`, который стирает следы прошлого запуска.
- **Предупреждение:** сквозной тест и снимки не запускаются на базе с настоящими посетителями: `db:seed` сотрёт их заявки и уведомления основного набора.

## Сервер
`compose.yaml` в корне репозитория и `app/Dockerfile` описывают запуск на сервере: приложение и PostgreSQL 18, порт базы наружу не публикуется. **Они не запускались**: на ноутбуке разработки Docker нет. Первая проверка — пакет 2.5.

## Где что лежит
| Папка | Что |
|---|---|
| `src/app/` | Страницы и действия на сервере. Базу и `process.env` напрямую не трогают |
| `src/server/dal/` | Слой доступа к данным: единственное место с запросами к базе ([ADR-0002](../docs/adr/ADR-0002-data-access.md)) |
| `src/server/auth/` | Вход, сессии, кука, хеш пароля ([ADR-0003](../docs/adr/ADR-0003-auth-sessions.md)) |
| `src/server/config.ts` | Единственное место с `process.env` ([ADR-0004](../docs/adr/ADR-0004-secrets-config.md)) |
| `src/lib/` | Чистая логика без базы: даты, заявки, сводка оценок |
| `db/` | Миграции, вымышленные данные, скрипты подготовки |
| `tests/unit/`, `tests/e2e/` | Модульные и сквозные тесты ([ADR-0005](../docs/adr/ADR-0005-security-checks.md)) |
