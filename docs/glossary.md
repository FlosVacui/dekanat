# Глоссарий

Термины проекта. В документах и в интерфейсе используются эти слова, а не их синонимы.

## Процесс
| Термин | Значение |
|---|---|
| Пакет | Пункт графика с владельцем, исполнителем и сроком, например 3.2 |
| Этап | Группа пакетов с общим итогом; заканчивается воротами |
| Ворота | Проверка этапа: приёмка, оценки ролей, решение пользователя |
| Веха | Дата с проверяемым состоянием продукта: М0, М1 |
| Смена | Работа одного разработчика от `/start` до `/handoff` |
| Точка сохранения | Состояние, с которого может продолжить другой человек: коммит, запись в журнале, пункт «что дальше» |
| Передача смены | Обновлённый `docs/HANDOFF.md` и промпт для следующей сессии |
| Зона | Набор файлов с владельцем по умолчанию: А — основа, Б — экраны, В — люди и материалы |
| Разработчик | Человек, который сейчас ведёт смену: участник А, Б или В. В колонке «Исполнитель» ROADMAP то же слово значит роль `builder` |
| Пользователь | Участник А. Решает развилки и подтверждает публикацию, изменение доступа, загрузку видео, отправку работы и покупки — и в сменах участников Б и В |
| Оркестратор | Основная сессия Claude текущей смены: ставит задания, принимает работу, ведёт учёт |
| Субагент | Отдельный запуск модели с ролью из `.claude/agents/` и своим контекстом |
| Задание | Самодостаточная постановка для исполнителя по шаблону `templates/brief.md` |
| Развилка | Вопрос Р-x, который решает пользователь |
| Учёт | `docs/tracker/tracker.yaml` и команды `tools/tracker.py` |
| Реестр промптов | `prompts/INDEX.md`: итоговые версии промптов с привязкой к этапу и функции |
| Журнал ошибок ИИ | `docs/evidence/ai-errors.md`: что ИИ сделал не так, как заметили, как исправили |
| Правдивая витрина | Правило: жюри видит чистый репозиторий, и всё показанное — настоящее |
| ВН | Запрос во внешнюю нейросеть, который отправляет человек |

## Продукт
| Термин | Значение |
|---|---|
| Кабинет | Личный кабинет студента — сам прототип |
| Ядро | Пять обязательных разделов: вход и профиль, расписание, успеваемость, заявки и справки, уведомления |
| Сквозной сценарий | Вход → расписание → оценки → заявка → статус |
| Заявка | Заказ справки или заявление, поданное онлайн; имеет статус |
| Кабинет сотрудника | Страница сотрудника деканата, где меняется статус заявки |
| Тестовый аккаунт | Вымышленный пользователь для жюри; логин и пароль публикуются |
| Концепт | Пометка на сайте: прототип для конкурса, не официальный сервис вуза |
| Чужие данные по адресу | Попытка открыть запись другого пользователя, подставив её номер в адрес страницы или запроса |
| Атакующий тест | Автотест, который пробует нарушить защиту и должен получить отказ |

## Конкурс
| Термин | Значение |
|---|---|
| Жюри | Конкурсная комиссия; оценивает по четырём критериям до 10 баллов |
| «Жюри» (в кавычках) | Роль субагента, которая ставит баллы на воротах так, как это сделало бы жюри |
| Капитан | Участник, который отправляет работу в кабинете конкурса |
| Описание процесса | PDF со скриншотами о том, как шла работа с ИИ; часть сдачи |
