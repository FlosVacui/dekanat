## Что сломано или под сомнением
- **Правки после аудита другой агент не смотрел.** Их доказывают тесты аудитора, прошедшие без пометки, и общая проверка. Повторный взгляд — аудит 4.4.
- **Политика содержимого разрешает встроенные скрипты** — `'unsafe-inline'`: [IMP-017](ISSUES.md). В режиме разработки добавляется `'unsafe-eval'`; этот режим в браузере под политикой не проверялся.
- **П-12 между наборами проверена только на слое доступа:** второго набора в основной базе нет. П-04 по HTTP шла с номером заявки Б вместо номера пользователя Б; с номером пользователя — на слое доступа.
- **Версия Next.js сверена только с рубежом ресерча на 11.11.** Свежие бюллетени аудитор не открывал. При установке зависимостей npm сообщал о 13 уязвимостях средней серьёзности: проверки Д-01 и Д-02 — ворота 3.
- **`.dockerignore` и сборка образа** запуском не проверены: Docker на машине нет.
- **Файлы Compose никто не запускал.** Замечания к ним — [IMP-016](ISSUES.md), шесть пунктов. Первая проверка — на сервере, пакет 2.5. Сервер покупается до 15.11, М0 на хостинге — к 16.11: на починку один день.
- **Сквозной тест, снимки и атакующие тесты меняют базу:** `db:seed` возвращает основной набор в исходное состояние. На базе с настоящими посетителями их запускать нельзя.
- **Локальная база** после перезагрузки ноутбука не отвечает: её запускают заново отдельным процессом — [B-2.4-e2e](briefs/B-2.4-e2e.md), раздел «Ловушки».
- **Числа лимита смен 7 и 8 не сходятся:** недельный лимит упал с 20 % до 16 % без сброса. Пользователь ответил: профиль один. Причина не выяснена.
- Прежние: `db:seed` не откатывает статус заявок, изменённый руками, — не проверялось; ширина подписи «Успеваемость» на телефоне не мерилась; «чистую машину» по `app/README.md` никто не прошёл целиком; утверждения «по знанию аудитора» в ADR не сверены; публичный аккаунт можно портить внутри своего набора — ответ в пакете 3.8; решения ворот 1 приняты без голоса студентов; лицензии инструментов разработки не сверены ([IMP-007](ISSUES.md)).
