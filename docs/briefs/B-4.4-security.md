## Что сделать
**Промежуточный итог — после каждого пункта:** две-три строки в файл `%LOCALAPPDATA%\dekanat-runs\sec-4.4-progress.md`, файл перезаписывай целиком инструментом записи. Отчёт начни писать рано и дополняй.

1. **Список адресов и действий.** По коду `app/src/app/` — полный список страниц и серверных действий на сегодня: адрес, кто вправе, есть ли номер записи или ввод посетителя в адресе или в теле. Сравни со списком в SEC-3.10 и отметь новое.
2. **Посредник `app/src/proxy.ts`.** Можно ли обойти отказ 403 для POST без `Origin` или с `Origin` не-адресом: регистр и повтор заголовка, пробелы, `Origin` с путём или портом, другие методы запроса к действию, адреса под исключениями `matcher` — `_next/static`, `_next/image`. Битая кодировка адреса — экран «не найдено», не 500. Доказательство — данные не изменились, а не только код ответа.
3. **IMP-043 — сверка хоста.** Правильный, но чужой `Origin` (`https://evil.example`) сейчас проходит посредник, и Next.js отвечает 500. Сделай:
   - атакующий тест: отметка «прочитано» и смена статуса с чужим `Origin` — действие не выполнено, метка данных не изменилась; код ответа — запиши, какой есть;
   - по `action-handler.js` — точное правило Next.js: какие заголовки он сравнивает, что делает при `x-forwarded-host`, что считает разрешённым;
   - по `deploy/Caddyfile` — какие `Host` и `X-Forwarded-Host` получит приложение за Caddy, со ссылкой на документацию Caddy или на «не проверено» с причиной;
   - в отчёт — проект сверки хоста в посреднике, который совпадает с правилом Next.js и за Caddy не закроет вход, и список проверок на сервере после выкладки: запросы `curl` без данных входа и вход пользователя с телефона. Код посредника не меняй.
4. **R-3.10-6 — события отказа без предела.** Событие `access_denied_record` пишется при каждой подделке номера; предел «30 смен в минуту» считает только `request_events` и подделки не видит. Журнал — строка JSON в стандартный вывод (`security-log.ts`), на сервере — предел журнала контейнера 10 МБ × 5 файлов. Измерь на стенде: сколько строк в минуту пишет один вошедший пользователь подделкой номера в отметке «прочитано», в смене статуса и на странице чужой заявки; размер строки; за сколько минут такой поток вытеснит из журнала 50 МБ прежних событий. Дыра — тест с пометкой и номером R-3.10-6, рядом контрольный. В отчёт — вариант предела и его цена.
5. **Фильтр и поиск у сотрудника** — `/staff/requests?status=…&q=…`, вид от 1024 px. Ввод в `q` и `status`: строка с разметкой и скриптом выводится как текст; длина больше 100 знаков; знаки вне ASCII и перевод строки; неверный `status`. Сотрудник одного набора поиском по ФИО не находит заявок другого набора — доказательство чужой меткой. Запрос к базе — проверь чтением кода, есть ли в нём ввод посетителя.
6. **Вид на компьютере от 1024 px.** Студент не видит ссылок и данных сотрудника и наоборот, ни в боковой навигации, ни в разметке страницы. Проверка — в браузере Playwright на 1280 px.

## Как писать тесты
- **Где.** Только `app/tests/security/`: новый файл `gate4.spec.ts` или `gate4.test.ts` и новые тесты в существующих файлах. Проверки по HTTP и в браузере — Playwright, `*.spec.ts`; слоя доступа и базы — Vitest, `*.test.ts`. Обе папки уже подключены в настройках: настройки не меняй.
- **Доказательство — чужая метка или неизменные данные, а не код ответа.**
- **Находка.** Дыра найдена — тест остаётся с пометкой `test.fail` в Playwright или `test.fails` в Vitest и с номером замечания в названии. Рядом — контрольный тест без пометки: стенд жив, вход работает.
- **Проверка держится** — тест без пометки остаётся.
- **Прежние тесты не ослабляй и не удаляй.** Правка ломает чужой тест в `app/tests/e2e/`, `app/tests/unit/` или `app/tests/security/` — верни прежний вид и вопрос в отчёте: ошибка ИИ 97.
- **Сервер для тестов** — помощники `app/tests/e2e/helpers/server.ts`, порт 3100: импортировать можно, менять нельзя. Твои файлы не должны зависеть от порядка запуска. Второй набор создаёшь — удаляешь сам, как `gate3.spec.ts`.
- **После правки тестов — `(cd app && npx tsc --noEmit)`:** vitest типы не проверяет, а `next build` в сквозном прогоне проверяет и тесты — ошибка ИИ 134.
- Комментарии в тестах — по-русски, коротко: что атакуем и по какой проверке.

## Ловушки
- **Файлы пишутся только инструментом записи или правки, не `sed -i`.** Heredoc нельзя — ни для файлов, ни для `python`, ни для `node`: скрипт запиши файлом в `%LOCALAPPDATA%\dekanat-runs\` и запусти оттуда — ошибка ИИ 104.
- **Команду с `cd` бери в скобки:** `(cd app && ...)`.
- **Машина нестабильна:** процессы Node.js падают с кодами `3221225477` и `3221225622`. Команды `npm`, `npx` и `node` — только так, из Git Bash: `(cd app && cmd //c "start /b /wait /affinity FFFF0000 npm test")`. Голый `npx vitest` без `npm test` падает в глобальной настройке. `cmd start` не передаёт код возврата: итог читай по строкам `passed` и `failed`. Упал процесс с таким кодом или Chromium с «Page crashed» без проваленных по существу проверок — повтори один раз и назови оба результата.
- **Локальная база** — `127.0.0.1:5432`. Перед прогоном: полный путь `%LOCALAPPDATA%\dekanat-pg\pgsql\bin\pg_isready -h 127.0.0.1 -p 5432`, смотри код возврата. Не отвечает — не чини, верни в ответе. Базу не останавливай.
- **Право.** Отказ базы делается отзывом права чтения — образец в `app/tests/e2e/states.spec.ts`; отозвал — верни в `finally` того же скрипта. Процесс погиб между отзывом и возвратом — право возвращает `npm run db:migrate`, а не `npm run db:seed`.
- **`.env` не читать.** Имена переменных — из `.env.example` и `app/src/server/config.ts`. Адрес базы скрипт берёт так же, как `app/tests/e2e/helpers/db.ts`.
- **Сборку с метками в `.next` не оставляй:** после такой проверки пересобери обычной `npm run build`.
- **Время бери с часов:** `TZ='<+03>-3' date`. Время начала и конца в шапке отчёта — с часов, не по памяти: ошибки ИИ 101 и 129. С 23:50 до 00:05 МСК сквозные тесты не запускай.
- **Селектор по подстроке даёт ложный успех** — ошибка ИИ 125. **Зелёный тест может ничего не проверять** — ошибка ИИ 115: у каждого нового теста убедись, что без защиты он был бы красным, хотя бы рассуждением в отчёте.
- **Сквозные тесты зависят от порядка файлов:** `m0.spec.ts` идёт раньше `notifications.spec.ts` и меняет ленту. Красный `schedule.spec.ts` или `grades.spec.ts` в непривычный день — сначала R-3.2-1 в [RV-3.2-1](../reviews/RV-3.2-1.md) и пункт 9 [RV-3.3-1](../reviews/RV-3.3-1.md).
- **Проверка чистоты** `tools/check_clean.py` ищет в документах личные пути и почту: в отчёте не пиши абсолютных путей этой машины и записей вида «пакет@версия».
- Путь к репозиторию содержит кириллицу и пробелы. Кириллица в `-g` через `cmd` может не найти тесты: перед запуском — `chcp 65001`.
- **Перед отчётом проверь, что твоих процессов не осталось:** `node`, `next`, `playwright`, `chromium`, `bash`, `python` с папкой проекта, `.next` или `dekanat-runs` в командной строке. Останови только свои. Чужие `node` и `chrome` не трогай: на машине идёт другой проект; процесс `uv run --no-project python scripts/check_all.py` — тоже чужой.
- Работай только с локальным стендом. Сайт в интернете, сервер и настоящие системы вуза не трогаются; данные входа на рабочем сайте не вводятся.
