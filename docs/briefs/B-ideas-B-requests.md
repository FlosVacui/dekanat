# B-ideas-B — заявки: одна фраза, мгновенная справка с QR, «Требуют ответа», этапы, просрочка

19.11.2026. Исполнитель — субагент общего назначения с ролью `builder` (`.claude/agents/builder.md`), Sonnet 5.5 / high. Решение пользователя (участник А) 19.11: пять идей из `idei-100.md` и анализа кабинетов вузов делаются в эту смену. Развилка Р-5 («ИИ-помощник до сдачи не делаем») этим заданием не отменяется: языковую модель не подключаем, ключей нет.

## Что сделать
1. **Заявка одной фразой** (идея №1) на `/requests/new`. Над формой поле «Опишите, что нужно» и кнопка «Заполнить». Разбор на сервере, по ключевым словам и датам (`app/src/lib/intent.ts`, чистая функция): тип справки из `REQUEST_KINDS` (военкомат, по месту требования, об оплате для вычета и т. д. — по тем типам, что есть), назначение, срок («к пятнице», «до 25 ноября», «завтра»), число экземпляров. Результат — предзаполненная форма; студент проверяет и подаёт сам, автоподачи нет. Не распознано — честная строка «Не понял, выберите тип справки ниже». Подпись у поля: «Подбор по ключевым словам». Слово «ИИ» в интерфейсе не использовать. Без JS форма работает как раньше (прогрессивное улучшение через server action или GET-параметр).
2. **Мгновенная справка об обучении с QR** (идеи №7 и №8; прецедент — Oxford, enrolment certificate). Для типа «справка об обучении / по месту требования» (выбери ближайший существующий тип, назови в отчёте) — кнопка «Получить сразу». Создаётся заявка через существующий слой доступа сразу в статусе «готова» с событием в истории; открывается печатная страница справки (HTML с `@media print`, кнопка «Сохранить в PDF» = `window.print()`), на ней QR-код со ссылкой на `/verify/<код>`. Код — HMAC от id заявки на серверном секрете, который уже есть в проекте (найди по ADR и `scripts/with-env.mjs`; `.env` не читать; нет подходящего — верни вопрос). Миграций нет.
   Публичная страница `/verify/[code]` без входа: «Справка действительна», тип, сокращённое ФИО («Иванов И. И.»), курс и группа, дата выдачи. Неверный код — «Справка не найдена». Больше никаких данных. Пометка «Прототип. Данные вымышленные».
   QR — пакет `qrcode` (MIT), рендер в SVG на сервере. Лицензию проверь в метаданных пакета, строку добавь в `THIRD_PARTY.md`.
3. **Фильтр «Требуют ответа»** в списке заявок студента (прецедент — «Мои запросы» в ЦУ): переключатели «Все / В работе / Требуют ответа / Готовы». «Требуют ответа» — заявки, где ход за студентом (готова к выдаче, отклонена с возможностью исправить и т. п. — по существующим статусам и `StepState 'next_you'`). Фильтр через параметр адреса, без JS.
4. **Путь заявки по этапам** (идея №5): проверь `components/requests/steps.tsx`. Если дата у каждого пройденного шага уже показывается — ничего не делай и напиши об этом. Если нет, а события с датами хранятся — покажи дату у шага.
5. **Просроченная заявка наверху** (идея №39) в списке сотрудника `/staff/requests`: заявки после срока — первыми, красная метка «Просрочена на N дн.». Только сортировка и оформление. Срок — то поле, что уже есть; нет поля — напиши в отчёте и пропусти.

## Безопасность
Владелец — из сессии. Чужая заявка через «Получить сразу» и через печатную страницу — отказ. `/verify` не раскрывает id заявки и не перебирается: код — HMAC, сравнение постоянного времени.

## Тесты
Unit: `intent.ts` (не меньше 10 фраз, включая нераспознанную), HMAC-код (свой проходит, изменённый — нет), сортировка просроченных, фильтр «Требуют ответа». e2e — напиши файл `app/tests/e2e/ideas-requests.spec.ts` (фраза → предзаполненная форма; «Получить сразу» → страница с QR → `/verify` показывает «действительна»; чужой код → «не найдена»), но не запускай.
Запускай `cd app && npm run typecheck && npm run lint && npm test`. `next build` и e2e не запускай — их прогонит оркестратор.
