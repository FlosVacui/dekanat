## 1. Что не так сейчас и зачем проход
Снимки — `docs/evidence/screenshots/2026-11-19-4.1/1280-today.png`, `360-today.png`, `2026-11-18-redesign/1280-grades-semester-works-open.png`.
1. Каждый блок оформлен одинаковой карточкой: скругление 22 px, одна тень, кремовый фон. Перед каждым заголовком стоит оранжевая точка. Жёлтым залиты блок пары, подложка изменений и активный пункт меню. Если выделено всё, не выделено ничего.
2. На «Сегодня» четыре плитки с числами. «0 — сдать на этой неделе» ничего не сообщает, «14 уведомлений» повторяет колокольчик.
3. У блока пары синяя шапка со словом «Сегодня» — повтор заголовка страницы.
4. «Успеваемость» на 1280 px занимает 3200 px в высоту. У каждого предмета по две-три полноширинные кнопки-капсулы. Половина ширины экрана пустует.
5. Nunito, крупные скругления и кремовый фон вместе выглядят по-детски и шаблонно.

Цель прохода: интерфейс отвечает «что от меня нужно», цвет несёт только смысл. Раскладку разделов, маршруты и данные **не меняем**.

## 3. Токены — одна правка меняет все экраны
Файлы: `docs/design/tokens.css` (оригинал) → копия в `app/src/app/tokens.css`; `app/src/app/layout.tsx`; `app/package.json`; `THIRD_PARTY.md`. Имена токенов **не переименовывать** — меняются значения, утилиты Tailwind остаются те же.

Синий `--primary #194CA6`, оранжевый знака и цвета состояний не меняются. **Тёмную тему (`.dark`)** привести к тем же правилам: без жёлтой заливки активного пункта и пары, тень `none`. Значения подобрать по контрасту, правило системы — текст 4.6:1, графика 3.1:1. Пересчитать все пары обеих тем скриптом, как в прошлый раз, и записать итог в `docs/design/D-2.2-system.md`.

**Шрифт.** `npm i @fontsource-variable/golos-text` версии `5.3.0`, импорт в `layout.tsx` вместо Nunito, пакет Nunito удалить. Лицензия — OFL, строка в `THIRD_PARTY.md`. Внешних CDN нет. Цифрам оценок и времени — `font-variant-numeric: tabular-nums` (класс `.hero-time` уже есть, распространить на баллы и сроки).

**Глобально.**
- Убрать оранжевую точку перед заголовками разделов.
- Убрать вложенность «карточка в карточке», то есть подложку блока изменений.
- `text-wrap: balance` для h1–h3.

## 4. Экраны
Порядок: «Сегодня» → «Успеваемость» → остальные экраны только по токенам, без правки компонентов.

### 4.1 «Сегодня» — по макету `design-pass/today.html`
- **Заголовок — дата** («Четверг, 19 ноября»), подпись — группа и неделя. Слово «Сегодня» остаётся в меню.
- **Четыре плитки с числами убрать.** На их место — блок **«Ждёт вас»**: список строк по важности.
  - красная метка — долг (дисциплина, дата пересдачи, «стипендия не назначается», если это есть в данных);
  - жёлтая — нет допуска (сколько баллов не хватает, ближайшая работа);
  - зелёная — готовая или готовящаяся справка, ответ деканата на вопрос.
  - У строки с действием — одна кнопка-ссылка с глаголом: «Подготовиться к пересдаче» ведёт на страницу предмета, «Открыть работы» — на «Успеваемость» с раскрытым предметом, «Забрать справку» — на заявку.
  - Блок пуст — одна строка «Всё в порядке: долгов и ответов от вас не ждут».
  - **Данные — только существующие функции из `lib/`**: `grades` (долги, допуск), `requests`, `questions`. Новых таблиц и миграций нет. Это перекомпоновка экрана, а не новая функция, поэтому в заморозку укладывается.
- **Пара:** без синей шапки. Слева время 30 px и «до 11:45», справа дисциплина, вид и преподаватель. При смене аудитории: «Аудитория **2-108** ~~1-412~~», новая аудитория на жёлтой плашке. Под блоком — ссылка «Расписание на неделю».
- **Изменения** — строки списка без жёлтой подложки, плашки видов из М2 остаются (цвета видов не трогать).
- **Мои заявки** — строки со статусом справа.
- От 1024 px — две колонки: слева «Ждёт вас» и пара, справа изменения и заявки. На телефоне — в этом же порядке столбцом.

### 4.2 «Успеваемость»
- Сводка «Как у меня дела» — без изменений по смыслу. От 1024 px закрепить её слева (`position: sticky`), список предметов — справа.
- Предмет — строка: название, итог-плашка, полоса баллов с отметкой допуска. **Вся строка — ссылка на страницу предмета.** Кнопку «Страница предмета» убрать.
- «Все работы (4)» — через `<details name="works">`: аккордеон без JS, одновременно открыт один предмет. Кнопку-капсулу заменить на строку-переключатель.
- Таблица работ: контейнерный запрос (`container-type: inline-size`) — таблица при ширине от 560 px, список при меньшей.
- Предмет с долгом наверху, рамка ошибки остаётся (это уже есть).

### 4.3 Остальные экраны
Расписание, заявки, уведомления, «Спросить деканат», кабинет сотрудника меняются только через токены. Если после токенов где-то останется кремовый фон или точка у заголовка — убрать точечно и записать список в итог `builder`.

## 5. Переходы
Только как отклик на действие. Всё выключается при `prefers-reduced-motion: reduce` — правило уже есть, сохранить.
1. **Раскрытие «Все работы»** — `interpolate-size: allow-keywords` и `transition` высоты у `details::details-content`, 200 мс, `ease-out`. Где не поддерживается — открывается сразу.
2. **Предмет → страница предмета** — общий элемент: название предмета перетекает в заголовок. `experimental.viewTransition` в `next.config`, `<ViewTransition name={'subject-'+id}>` вокруг названия в строке и в заголовке страницы. Сначала проба на нашей версии Next 16.4 / React 19.3. Если сборка или e2e падают — откатить пункт 2 и записать в `ai-errors.md` или `ISSUES.md`, что не взлетело.
3. **Переход между разделами** — перетекание 150–200 мс. Только если пункт 2 взлетел без ошибок.

**Не делать:** появление блоков при загрузке и прокрутке, подъём карточек при наведении, пружины, скелеты с новыми эффектами.

## 7. Порядок работ и субагенты
1. `/start`, развилка части 2, ветка `feat/design-pass` от свежего `main`.
2. Задание `docs/briefs/B-design-pass.md` по шаблону репозитория. Содержание — части 3–6 этого файла по ответу участника А. Промпт задания — в `prompts/`.
3. `builder`, Sonnet 5.5 / high. Порядок: токены и шрифт → «Сегодня» → «Успеваемость» → переходы → идеи 6.2–6.3 → 6.4 по слову. После каждого шага — `npm run check` и снимки.
4. **Тесты.** Строки, которые меняются («Следующая пара · …», плитки, кнопка «Страница предмета»), правятся в тестах только как «было → стало», с перечнем в итоге `builder`. Новые e2e: блок «Ждёт вас» у студента 1 (долг, нет допуска, справка) и у студента 2 (своё, чужого нет); раскрытие одного предмета закрывает другой.
5. **Снимки** 360 и 1280 px: «Сегодня», «Успеваемость» с раскрытыми работами, страница предмета, расписание дня, заявка, кабинет сотрудника — в `docs/evidence/screenshots/2026-11-20-design-pass/`. Снимок «до/после» «Сегодня» — туда же.
6. **Контраст** — скрипт пересчёта пар обеих тем; итог в `D-2.2-system.md`.
7. `reviewer` со свежим контекстом → `docs/reviews/RV-design-pass-1.md`. Отдельно проверить: чужие данные в «Ждёт вас» не видны, владелец берётся из сессии; фокус с клавиатуры виден на новых строках-ссылках и `<summary>`; нижняя панель не закрывает фокус.
8. `uv run tools/check_all.py`, коммит работы, PR — по слову участника А. Слияние и выкладка на сервер — участник А со своей машины.
9. Ворота 4 (аудит 4.4, проверка 4.3) идут **после** слияния прохода: задания уже требуют проверять новые экраны.
10. Точка сохранения: журнал, `tracker.py mark/log`, HANDOFF, промпт следующей смены. Ошибки ИИ — по факту, со следующего свободного номера.
