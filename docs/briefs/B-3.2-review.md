## Ловушки
- **Машина нестабильна:** процессы Node.js падают с кодами `3221225477` и `3221225622`, 14.11 был синий экран — [R-node-crashes](../research/R-node-crashes.md). Команды `npm` запускай только так, из Git Bash: `(cd app && cmd //c "start /b /wait /affinity FFFF0000 npm test")`. Без привязки три прогона подряд были красные.
- Команда упала с кодом падения процесса или оборвала соединение — `ECONNRESET`, уход на `/login`, «This page couldn’t load», — а проваленных по существу проверок нет: повтори один раз и назови оба результата в отчёте. Упала дважды в одном месте — это находка.
- **Команду с `cd` бери в скобки** — иначе рабочая папка останется в `app/`: ошибка 80.
- **Локальная база** — PostgreSQL на `127.0.0.1:5432`. Проверка перед каждым прогоном: полный путь `%LOCALAPPDATA%\dekanat-pg\pgsql\bin\pg_isready` с параметрами `-h 127.0.0.1 -p 5432`; смотри код возврата, а не текст. Не отвечает — не чини: остановись и верни в ответе.
- **Сегодня — суббота 14.11.2026;** после полуночи по Москве — воскресенье, день без пар. «Сегодня» считает сервер в часовом поясе из настроек. Один зелёный прогон не доказывает, что тест верен в другой день: пункты 2 и 5 проверяй чтением плана набора в `app/db/seed-lib.ts`.
- `npm run db:seed` стирает заявки основного набора локальной базы. Сквозные тесты делают это сами — это нормально. Свои пробы данных — тестами на тестовой базе или в транзакции с откатом.
- Собранный файл стилей минифицирован в одну строку: ищи в нём только `grep -F` — ошибка 83. Большие файлы читай по строкам, а не целиком.
- Путь к репозиторию содержит кириллицу и пробелы: в командах — в кавычках. Порты 3000, 3100 и 5432 общие. Свои процессы останови перед отчётом; базу не останавливай.
- Перед работой: `git status --short` и `git log --oneline -3` — ты на `feat/3.2-schedule`; верхние коммиты — записи смен, код пакета — в коммитах из таблицы выше.
- Длинный текст в файл пиши инструментом записи, а не командой оболочки — ошибка 81.
