`reviewer` — Sonnet 5.5 / high. Раунд 1.

А; ветка `docs/0-close`. Она лежит в отдельной рабочей копии `../dekanat-stage0` рядом с основной папкой репозитория. Полный путь копии оркестратор называет при запуске. **Работай только в копии.** В основной папке в это же время работает другая сессия: там не читай, не пиши и не запускай команды. Ветку не переключай.

## Цель
Жюри оценивает не только продукт, но и то, как шла работа с ИИ. Доказательства — реестр промптов, журнал ошибок ИИ, перечень инструментов и список сделанного вручную. Их вёл оркестратор и сам себя не проверяет. Нужно независимо узнать: выполнен ли критерий пакета «реестр промптов, журнал ошибок ИИ, перечень инструментов заведены и заполнены», сходится ли каждая запись с git и журналом и нет ли в записях выдуманного, секретов и личных данных.

## Что сделать
1. **Реестр промптов — полнота.** Каждый файл из `prompts/` и `prompts/handoff/`, каждое задание из `docs/briefs/` и каждый запрос из `docs/external/` есть строкой в `prompts/INDEX.md`. И наоборот: каждая строка реестра ведёт на существующий файл. Составь таблицу: файл — есть ли строка.
2. **Реестр промптов — достоверность.** Для каждой строки сверь дату, этап, адресата и колонку «Что получилось» с журналом; колонку «Коммит» — с `git log`: коммит существует и действительно содержит этот файл или результат. Строки «ещё не отправлен», «ещё не запущен»: верно ли это на сегодня.
3. **Промпты как есть.** Реестр обещает итоговые версии — те, что отправлены ИИ. Нет ли в файлах промптов следов правки задним числом: посмотри `git log --follow` по каждому файлу `prompts/handoff/`. Правка после отправки без пометки в файле или реестре — замечание.
4. **Журнал ошибок ИИ.** Для каждой строки: смена существует в журнале; место из колонки «Где видно» существует и показывает эту ошибку; запись журнала смены называет эти номера. Нет ли пропусков и повторов в нумерации. Не смягчена ли запись после исправления: `git log -p docs/evidence/ai-errors.md`. Нет ли в журнале смен и в отчётах ревью ошибки ИИ, которой в этом файле нет, — выбери для проверки три отчёта ревью.
5. **Перечень инструментов.** Каждый инструмент из строк «Инструменты смены» журнала есть в `tools.md`, и наоборот: у каждой строки `tools.md` есть смена, где инструмент применён. Нет ли в перечне планов вместо применённого.
6. **Сделано вручную.** Каждая строка `manual.md` сходится со строкой «Сделано человеком» журнала той же смены. Не приписано ли человеку то, что сделал ИИ, и наоборот.
7. **Правила снимков.** `docs/evidence/screenshots/README.md`: ясно ли, что, когда и под каким именем снимать, и что на снимке не должно быть видно. Сходится ли с PROCESS и с шаблоном задания. Снимков в `main` ещё нет — это не замечание.
8. **Чистота.** Во всех проверяемых файлах: нет секретов, ключей, паролей, личных путей, почты, имён людей, названий других проектов. Запусти `uv run tools/check_clean.py`; затем посмотри глазами то, чего шаблоны проверки могут не ловить.
9. **Выдуманное.** Число, дата или цитата пользователя, которых нет ни в журнале, ни в git, — блокирующее замечание.
10. Напиши отчёт. В конце — раздел «Что переделать автору» по убыванию серьёзности, каждое — одним действием, с файлом.
