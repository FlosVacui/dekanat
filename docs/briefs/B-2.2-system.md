Задание самодостаточное: чата оркестратора ты не видел. Макеты уже собраны по заданиям [B-2.2-variants](B-2.2-variants.md) и [B-2.2-hybrid](B-2.2-hybrid.md). Пользователь 13.11.2026 выбрал вариант **АВ** — оформление «Тёплого», раскладка «Спокойного». Твоя работа — превратить макет в дизайн-систему, по которой сегодня же начнут писать экраны пакетов 3.2–3.7.

## Роль, модель, effort
`designer` — Sonnet 5.5 / high.

## Участник и ветка
Участник А доводит пакет участника Б; параллельная смена 13.11.2026. Ветка `docs/2.2-finish`; не переключай. Работай только в рабочей копии, путь — в сообщении запуска. В соседние папки не заходи.

## Цель
Один документ и один файл переменных, по которым исполнитель экрана собирает кнопку, карточку, поле и состояния без вопросов и без подбора цветов на глаз. Критерий плана: «Цвета, шрифты, компоненты; логотип не копирует официальный; лицензии записаны». Логотип и лицензии ведёт оркестратор, твоя часть — цвета, шрифты, размеры, компоненты.

## Что сделать
1. **Собери `docs/design/tokens.css`.** Переменные варианта АВ из `V-AC.html`: блок `:root` — светлая тема, блок `.dark` — тёмная. Имена не меняй. Значения не перепечатывай руками: достань скриптом и сверь скриптом же, что набор имён и значений совпал с макетом. Внизу файла — блок `@theme inline` для Tailwind 4, который отдаёт эти переменные утилитам (`--color-*`, `--radius-*`, `--font-sans`), и комментарий в начале файла: откуда значения и как подключить. Добавь `--font-sans: 'Nunito Variable', 'Nunito', system-ui, -apple-system, 'Segoe UI', Roboto, sans-serif`.
2. **Подними запас контраста.** В макетах он впритык: у самых слабых пар 0,01–0,04 над порогом ([ошибка Б-9](../evidence/ai-errors.md)). Пересчитай все пары обеих тем скриптом на Python по формуле WCAG 2.x. Правило системы: текст — не ниже 4,6:1, крупный текст и графика — не ниже 3,1:1. Пару ниже правила исправь сдвигом значения в `tokens.css` и запиши в документе «было — стало». Цвета знака `#194CA6` и `#E9661C` не меняются: если пара с ними не дотягивает, назови её и правило, которое её запрещает (как сейчас: оранжевый не пишется мелким текстом на белом). Изменил значение — `V-AC.html` не трогай; расхождение макета и системы перечисли в документе отдельной таблицей.
3. **Напиши `docs/design/D-2.2-system.md`** — частями, не одним вызовом. Разделы:
   1. Как пользоваться: что читать исполнителю экрана, в каком порядке.
   2. Цвета: таблица «переменная — светлая — тёмная — для чего», затем таблица пар «текст или значок — фон — контраст в светлой — в тёмной — порог — источник порога в R-1.3». Числа — из твоего скрипта.
   3. Шрифт и текст: Nunito, начертания, шкала размеров и высот строки от мелкой подписи до заголовка, цифры времени, минимум размера, поведение при увеличении до 200 %.
   4. Размеры: шаг отступов, скругления, тени, ширина 360 как основа, зона касания.
   5. Компоненты — по одному подразделу: кнопка (главная, вторая, с рамкой, опасная; состояния: обычная, нажата, фокус, выключена, ждёт ответа), карточка, поле ввода (подпись, подсказка, ошибка, фокус), плашка статуса (все виды из макета: отменена, перенесена, срок, в работе, готово), пустое состояние, ошибка, загрузка. У каждого: когда применять, размеры, переменные, роль и атрибуты для экранного чтеца, чего не делать, кусок разметки HTML с классами макета. Для кнопки и карточки — строка «как ложится на `app/src/components/`»: что там есть сейчас и что поменяется.
   6. Каркас экрана: шапка, нижняя панель из четырёх вкладок, пометка «концепт для конкурса» — кратко, со ссылкой на макет.
   7. Правила знака: размеры, поля, плашка в тёмной теме, где знак не ставится.
   8. Не только цвет: как показаны отмена, перенос, шаги заявки.
   9. Что не проверено и что отложено.
4. **Собери витрину `docs/design/system/index.html`:** одна страница без скриптов и внешних ссылок, подключает `../tokens.css`; на ней все семь компонентов во всех состояниях, светлая и тёмная тема рядом, колонки шириной 360 px. Шрифт — системный запасной: файлов Nunito нет.
5. **Сними витрину** в `docs/evidence/screenshots/2026-11-13-2.2/system-1280.png` и открой снимок инструментом чтения. Наезд, обрезка, нечитаемая пара — исправь и сними заново, не больше трёх кругов. Отдельно проверь скриптом в Edge через `iframe` шириной 360: нет прокрутки вбок, зоны касания не меньше 44×44.

## Ловушки
- **Edge без окна не делает окно у́же примерно 500 px** — снимок только на 1280; ширину 360 проверяй через `iframe`: [ошибка Б-5](../evidence/ai-errors.md). Команда: `"C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" --headless --screenshot=<файл> --window-size=1280,<высота> <адрес file:///…>`. Нет Edge по этому пути — поищи `msedge.exe` в `C:\Program Files\Microsoft\Edge\Application\`; не нашёл — верни вопрос, снимок не выдумывай.
- **Не оставляй оболочку в подпапке:** команды — из корня рабочей копии ([ошибка Б-7](../evidence/ai-errors.md)).
- **Windows.** Правки файлов — инструментом редактирования, не `sed` и не `cat >>`. Кодировка — UTF-8. Python — через `uv run python`; скрипты в репозиторий не клади.
- **Латинская «B» вместо русской «В»** в названии варианта уже случалась ([ошибка Б-8](../evidence/ai-errors.md)): вариант называется «АВ» русскими буквами.
- Числа контраста и размеров — только из скрипта. Лицензии и пороги — только из названных документов, не по памяти: нет в документе — пиши «не проверено».
- Не читай `V-AC.html` целиком: файл большой, хватит поиска и скрипта.
- Облачко, приветствие по имени и сова в пустом состоянии в систему не входят: в варианте АВ их нет.
