## Ловушки
- **Правка ломает тест — верни прежний вид и вопрос.** Чужой тест после твоей правки красный: не правь тест, не подгоняй код вслепую и не оставляй тест красным. Верни этот кусок к прежнему виду, а в отчёте назови имя теста, текст ошибки и своё предложение — ошибка ИИ 97. Из существующих тестов ты правишь только `states.spec.ts` и название в `loading-boundary.test.ts`.
- **В `states.spec.ts` ни одна прежняя проверка не ослабляется и не удаляется без названной причины.**
- **Новых текстов интерфейса не придумывай** — ни видимых, ни подписей для экранного чтеца. Нужен текст — верни вопрос.
- **Зелёный тест может ничего не проверять** — ошибка ИИ 115. Проверка фокуса должна быть красной до правки шага 2 и зелёной после.
- **Отзыв права и блокировки.** `states.spec.ts` отзывает у роли приложения право чтения таблиц и берёт блокировки. Процесс тестов погиб между отзывом и возвратом — право остаётся отозванным; `npm run db:seed` его не возвращает, возвращает `npm run db:migrate`. Красные все тесты подряд — проверь право: `%LOCALAPPDATA%\dekanat-runs\3.7-check-privilege.mjs`, запуск с переменной `REPO_DIR` — путь к репозиторию в виде Windows.
- **Тесты не зависят от дня недели и часа запуска** — ошибки ИИ 84, 115 и 120. Время бери с часов: `TZ='<+03>-3' date`. Между 23:50 и 00:05 МСК сквозные тесты не запускай.
- **Сквозные тесты зависят от порядка файлов.** Доказательство для своего файла — прогон одного файла сразу после `npm run db:seed`, и затем полный прогон.
- **Машина нестабильна:** процессы Node.js падают с кодами `3221225477` и `3221225622` — [R-node-crashes](../research/R-node-crashes.md). Команды `npm`, `npx` и `node` — только с привязкой к ядрам, из Git Bash: `(cd app && cmd //c "start /b /wait /affinity FFFF0000 npm test")`. `cmd start` не передаёт код возврата: итог читай по строкам `passed` и `failed`. Команда упала с таким кодом, оборвала соединение или упал Chromium с «Page crashed», а проваленных по существу проверок нет: повтори один раз и назови оба результата. Упала дважды в одном месте — ищи причину.
- **Общую проверку `tools/check_all.py` не запускай:** её прогонит оркестратор. У неё нет справки: любой параметр запускает полный прогон.
- **Команду с `cd` бери в скобки** — ошибки ИИ 80 и 104. Файлы правь только инструментом записи или редактирования, а не командой оболочки: `mv`, `cp`, `sed -i` для файлов репозитория нельзя — ошибка ИИ 124. Heredoc нельзя — ни для файлов, ни для `python`, ни для `node`: свой скрипт запиши файлом в `%LOCALAPPDATA%\dekanat-runs\` инструментом записи и запусти оттуда.
- **Локальная база** — `127.0.0.1:5432`. Перед прогоном: полный путь `%LOCALAPPDATA%\dekanat-pg\pgsql\bin\pg_isready -h 127.0.0.1 -p 5432`, смотри код возврата. Не отвечает — не чини, верни в отчёте. Файл `.env` не читай.
- `npm run test:e2e` сам заполняет базу и собирает продукт; два прогона одновременно не запускай. Свой сервер поднимай на отдельном порту и останови.
- Путь к репозиторию содержит кириллицу и пробелы. Большие файлы читай по строкам.
- **Перед отчётом проверь, что твоих процессов не осталось:** `node`, `next`, `playwright`, `chromium`, `bash`, `python` с папкой проекта в командной строке. Останови только свои. Базу и чужие процессы `node` и `chrome` не трогай: на машине идёт другой проект.
