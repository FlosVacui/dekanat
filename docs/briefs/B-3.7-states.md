## Цель
У каждого экрана кабинета есть три состояния: пусто, ошибка, загрузка. Ошибка — не серый экран: сказано, что не получилось, что данные не потеряны, и есть «Повторить». ## Ловушки
- **Правка ломает тест — верни прежний вид и вопрос.** Чужой тест после твоей правки красный: не правь тест, не подгоняй код вслепую и не оставляй тест красным. Верни этот кусок к прежнему виду, а в отчёте назови имя теста, текст ошибки и своё предложение — ошибка ИИ 97. Существующие тесты ты не правишь.
- **Новых текстов интерфейса не придумывай** — ни видимых, ни подписей для экранного чтеца. Тексты — только из раздела решений, из этого задания и те, что уже есть на экране. Нужен ещё текст — верни вопрос.
- **Тесты держатся за разметку каркаса.** Не меняй: `data-testid="bell-count"`; подпись колокольчика с числом «Уведомления, непрочитанных: N»; подпись аватара; подписи и адреса четырёх вкладок; атрибут `data-tabbar`; отметку текущей вкладки. Каркас с данными после шага 1 даёт ту же разметку, что до него.
- **`error.tsx` — клиентский компонент.** Не тяни в него серверный код: слой доступа, сессию, настройки. Каркас без данных поэтому и нужен.
- **`notFound()`, `forbidden()` и `redirect()` — не ошибки.** Они не должны попадать в `error.tsx`: чужая и несуществующая запись по-прежнему неотличимы и дают «не найдено» — [ADR-0002](../adr/ADR-0002-data-access.md). Тесты безопасности это ловят.
- **Текст ошибки на экран не выводится:** ни `error.message`, ни служебный номер. В журнал сервера Next.js пишет сам.
- **`role="alert"` — только у карточки ошибки;** `aria-live="assertive"` к нему не добавляй.
- **Отзыв права — только в локальной тестовой базе и только на время теста.** Тест упал между отзывом и возвратом — следующие файлы и тесты безопасности станут красными: возврат в `finally` и в `afterAll` обязателен. Файл идёт после `schedule.spec.ts` и перед тестами безопасности.
- **Зелёный тест может ничего не проверять** — ошибка ИИ 115. Каждый цикл с проверками — с проверкой, что он прошёл больше нуля раз. Скелет, которого первую секунду не видно, тест должен дождаться, а не проскочить.
- **Тесты и снимки не зависят от дня недели и часа запуска** — ошибки ИИ 84, 115 и 120. Время бери с часов: `TZ='<+03>-3' date`. Между 23:50 и 00:05 МСК сквозные тесты и скрипты снимков не запускай.
- **Сквозные тесты зависят от порядка файлов:** прежние файлы оставляют в базе свои заявки и уведомления. Доказательство для своего файла — прогон одного файла сразу после `npm run db:seed`, и затем полный прогон.
- **Цвета и размеры — только переменными дизайн-системы:** `app/src/app/tokens.css`, блок `@theme inline`. Нужного нет — верни вопрос. Тёмную тему не включай. Новых зависимостей нет.
- **Машина нестабильна:** процессы Node.js падают с кодами `3221225477` и `3221225622` — [R-node-crashes](../research/R-node-crashes.md). Команды `npm` и `node` — только с привязкой к ядрам, из Git Bash: `(cd app && cmd //c "start /b /wait /affinity FFFF0000 npm test")`. `cmd start` не передаёт код возврата: итог читай по строкам `passed` и `failed`. Команда упала с таким кодом, оборвала соединение — `ECONNRESET`, уход на `/login`, «This page couldn’t load» — или упал Chromium с «Page crashed», а проваленных по существу проверок нет: повтори один раз и назови оба результата. Упала дважды в одном месте — ищи причину.
- **Общую проверку `tools/check_all.py` не запускай:** её прогонит оркестратор. У неё нет справки: любой параметр запускает полный прогон.
- **Команду с `cd` бери в скобки** — ошибки ИИ 80 и 104. Файлы правь только инструментом записи или редактирования, а не командой оболочки. Heredoc нельзя — ни для файлов, ни для `python`, ни для `node`: свой скрипт запиши файлом в `%LOCALAPPDATA%\dekanat-runs\` инструментом записи и запусти оттуда. Вывод команд в файл журнала вне репозитория перенаправлять можно.
- **Локальная база** — `127.0.0.1:5432`. Перед прогоном: полный путь `%LOCALAPPDATA%\dekanat-pg\pgsql\bin\pg_isready -h 127.0.0.1 -p 5432`, смотри код возврата. Не отвечает — не чини, верни в отчёте. Файл `.env` не читай.
- `npm run test:e2e` и скрипты снимков сами заполняют базу и собирают продукт; одновременно их не запускай. Свой сервер поднимай на отдельном порту и останови.
- Собранные стили минифицированы: только `grep -F` — ошибка ИИ 83. Большие файлы читай по строкам. Путь к репозиторию содержит кириллицу и пробелы. `tar` в Git Bash — только с `--force-local`.
- **Перед отчётом проверь, что твоих процессов не осталось:** `node`, `next`, `playwright`, `chromium`, `bash`, `python` с папкой проекта в командной строке. Останови только свои. Базу и чужие процессы `node` и `chrome` не трогай: на машине идёт другой проект.
