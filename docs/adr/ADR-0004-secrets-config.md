## Контекст
- Задание: ключи и пароли сервисов не лежат в коде и в браузере пользователя — ТР-9.3.
- Репозиторий станет публичным: Р-8. Всё, что попало в историю git, увидят все.
- С кодом работают ИИ-ассистенты. Чтение `.env` им запрещено настройками, но не проверено, закрывает ли запрет чтение через командную строку: IMP-008.
- В Next.js переменная с приставкой `NEXT_PUBLIC_` попадает в браузер; остальные остаются на сервере: R-1.5, раздел 3, строка «Секреты».

## Варианты
| Вариант | Плюсы | Минусы |
|---|---|---|
| А. Секреты в `.env` на сервере, в образ не входят, передаются при запуске | Просто; подходит одному серверу | Файл на сервере хранит человек; копию надо беречь |
| Б. Хранилище секретов провайдера | Удобнее при росте | Лишняя настройка для одного сервера; привязка к провайдеру |

## Решение
Вариант А — решение проекта.

**Какие секреты есть.** Пароль базы и строка подключения; пароли резервных тестовых аккаунтов; после решения по Р-5 — ключ модели. Ключа подписи сессий нет: [ADR-0003](ADR-0003-auth-sessions.md).

**Где лежат.**
- Настоящие значения — только в `.env` на сервере. Файл создаёт и хранит участник А.
- На ноутбуках — `.env` с локальными значениями, которые ничего не открывают: пароль локальной базы. Настоящих значений сервера на машинах, где работают ассистенты, нет. Так запрет чтения `.env` перестаёт быть единственной защитой.
- В git — только `.env.example`: имена переменных без значений.
- `.env*` стоит в `.gitignore` и в `.dockerignore`. Пакет 2.4 проверяет это сам: шаблон `create-next-app` добавляет строку в `.gitignore`, собранный руками проект — нет.

**В коде.**
- `process.env` читается в одном файле — `app/src/server/config.ts`, помеченном `server-only`. Остальной код берёт значения из него.
- Секрет никогда не получает имя с `NEXT_PUBLIC_`. Ключа `env` в конфигурации Next.js нет.
- Карты кода для браузера в рабочей сборке выключены.

**В образе Docker.** Секреты передаются контейнеру при запуске. В Dockerfile нет `ARG` и `ENV` с секретами.

**Заголовки.**
- В приложении: `X-Content-Type-Options: nosniff`, `Referrer-Policy`, `Permissions-Policy`, запрет встраивания в чужие страницы, политика содержимого без `unsafe-eval`; заголовок `X-Powered-By` убран.
- На обратном прокси: перенаправление на HTTPS и `Strict-Transport-Security`.
- Личные ответы — `Cache-Control: private, no-store`: [ADR-0002](ADR-0002-data-access.md).
- Полный текст политики содержимого пишется в пакете 2.6 на работающем приложении.

**Ошибки и журналы.**
- Посетитель видит общий текст ошибки. Текст внутренней ошибки, путь и запрос к базе наружу не уходят.
- В журнал не пишутся пароли, токены и куки сессий, ФИО и тела запросов целиком.
- В журнал пишутся события защиты: неверный вход, отказ в доступе, срабатывание лимита — с временем и номером пользователя.

**Проверки без чтения секретов.** Тесты подставляют вместо секретов метки и ищут метки в файлах для браузера и в журналах: R-1.5, проверки С-03 и Ж-02. Настоящие значения ассистент не читает и не печатает. `gitleaks` запускается только с `--redact`.

**Поправка к проверке С-05 по IMP-012.** Команда `docker history --no-trunc` печатает значения `ENV` и `ARG`. Она запускается только на тестовом образе, собранном с метками вместо секретов; её вывод с настоящего образа в отчёты не копируется.

## Последствия
- Что становится проще: одно место чтения окружения — одна строка поиска для аудитора; утечка локального `.env` ничего не открывает.
- Что становится сложнее: сервер настраивает человек; при потере `.env` сервера пароли задаются заново.
- Что нужно сделать: `.env.example` и `config.ts` — пакет 2.4; `.env` сервера — пакет 2.5, участник А; исключения `gitleaks` для публичных паролей основных тестовых аккаунтов — пакет 2.6, возможность не проверена: R-1.5, проверка Т-06.
- Слабое место: публичные пароли основных тестовых аккаунтов будут лежать в README и в комментарии к работе — так требует задание. Это не секрет сервиса, но сканер может принять их за находку.

## Простыми словами
Пароль от базы и другие ключи записаны в одном файле на сервере. В коде, в истории git и в том, что получает телефон, их нет. На ноутбуках, где с кодом работают ИИ-ассистенты, лежат только учебные значения, которые ничего не открывают. Проверки ищут в файлах сайта не настоящие ключи, а специальные метки: так проверяющему не нужно видеть сами ключи.
