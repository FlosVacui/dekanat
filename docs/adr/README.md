## Схема одним взглядом
```
Телефон студента ── HTTPS ──> обратный прокси (сертификат, HSTS)
                                   │
                                   ▼
                        приложение Next.js (контейнер)
                        ├─ страницы и действия на сервере
                        ├─ слой доступа к данным  ← единственное место запросов к базе
                        └─ конфигурация           ← единственное место чтения секретов
                                   │  внутренняя сеть Docker
                                   ▼
                        PostgreSQL (контейнер, порт наружу закрыт)
```
- Браузер получает готовую страницу. Запросов к базе и секретов в нём нет.
- Всё, что меняет данные, — действие на сервере. Отдельного открытого API в М0 нет: меньше адресов — меньше проверять.
- Снаружи открыт только обратный прокси. Порты приложения и базы наружу не публикуются.
- Обратный прокси и выпуск сертификата выбираются в пакете 2.5.
- На ноутбуке разработки Docker нет: база той же версии запускается без контейнера. Файлы Compose первый раз запускаются на сервере.

## Папки продукта
Продукт лежит в `app/`. Раскладка — намерение; пакет 2.4 может уточнить имена, но не правила.

| Папка | Что в ней | Правило |
|---|---|---|
| `app/src/app/` | Страницы и действия | Базу и `process.env` напрямую не трогают |
| `app/src/server/dal/` | Слой доступа к данным | Каждая функция получает того, кто спрашивает, из сессии: [ADR-0002](ADR-0002-data-access.md) |
| `app/src/server/auth/` | Вход, сессии, счётчики попыток — логика без клиента базы; запросы — в слое | [ADR-0003](ADR-0003-auth-sessions.md) |
| `app/src/server/config.ts` | Чтение переменных окружения | Единственное место с `process.env`: [ADR-0004](ADR-0004-secrets-config.md) |
| `app/db/` | Миграции, вымышленные данные, чистка | Настоящих имён нет: ТР-5. Скрипты — единственное исключение из правил «база только в слое» и «`process.env` только в `config.ts`»: это не часть работающего приложения |
| `tests/e2e/`, `tests/security/` | Сценарии на 360 пикселях; атакующие тесты | [ADR-0005](ADR-0005-security-checks.md) |

## Что решено пользователем и что — оркестратором
- **Пользователь:** стек (Р-3); сброса пароля и загрузки файлов нет; для тестовых аккаунтов — растущая задержка вместо блокировки и резервные аккаунты; CI локально; на ноутбуке разработки Docker не ставится. Источник — [журнал, смена 6](../history/JOURNAL.md) и [DECISIONS](../DECISIONS.md).
- **Оркестратор:** всё остальное в пяти ADR. Каждое такое решение помечено «решение проекта». Пользователь может его отменить.

## Что осталось открытым
1. **Библиотека запросов к базе.** Кандидаты — Drizzle и Prisma. По R-1.4, находка S5: лицензия Drizzle не подтверждена, у Prisma метка `latest` указывает на предвыпускную версию. Выбор — первый шаг пакета 2.4, по условиям из [ADR-0002](ADR-0002-data-access.md). По памяти лицензия не записывается.
2. **Обратный прокси и сертификат** — пакет 2.5.
3. **Политика содержимого (CSP)** — полный текст заголовка пишется на работающем приложении, пакет 2.6.
4. **Числа защиты от перебора и срок сессии** — выбор проекта, записан в [ADR-0003](ADR-0003-auth-sessions.md); источники дают только границы.
5. **Пароли тестовых аккаунтов в README** — задание требует их только в комментарии к работе. Вопрос пользователю, вместе с Р-8: [ADR-0004](ADR-0004-secrets-config.md).
6. **Утверждения «по знанию аудитора»** в ADR по документации не сверены: Docker и правила сетевого экрана, пул потоков для хеша, ключ шифрования действий на сервере.
7. **Отчёты R-1.4 и R-1.5 читались через пересказ страниц.** Числа OWASP и NIST человек не сверял: R-1.5, раздел 6; [IMP-011](../ISSUES.md).
