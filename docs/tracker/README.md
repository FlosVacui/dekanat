# Учёт проекта «Цифровой деканат»

Источник правды — `docs/tracker/tracker.yaml`. Из него скрипт `tools/tracker.py` собирает Excel
`График_работ.xlsx` (в git не хранится) и зеркалит пункты в Issues и на доску GitHub Projects.
Excel и доску только смотрят. YAML меняется только командами скрипта: статусы своих пакетов отмечает участник,
остальное — оркестратор. Порядок команд — `docs/PROCESS.md`, «Работа втроём с учётом».

Нужен [uv](https://docs.astral.sh/uv/): `tools/tracker.py` несёт зависимости (`openpyxl`, `PyYAML`) и версию Python в
собственных метаданных (PEP 723), `uv run` сам поставит их в кэш при первом запуске. Системный Python и `pip` не нужны.
Для `gh-sync` нужен GitHub CLI `gh` с правами `repo` и `project` (`gh auth refresh -s project`). Команды — из корня репозитория.

## Команды

```
uv run tools/tracker.py due                          # что просрочено, сегодня, завтра, ближайшие 3 дня
uv run tools/tracker.py due --days 3 --person Б      # окно 3 дня, только участник Б
uv run tools/tracker.py due --today 2026-11-06       # «сегодня» задан вручную (для проб)
uv run tools/tracker.py build                        # собрать Excel из YAML (атомарно)
uv run tools/tracker.py sync                         # прочитать заметки из Excel в YAML, затем build
uv run tools/tracker.py add --id 1.8 --title "Название" --person Б --owner "Sonnet 5.5 / high" \
       --review "Sonnet 5.5 / high" --start 2026-11-10 --end 2026-11-12
uv run tools/tracker.py mark 0.2 today "В работе"     # пункт, день, статус
uv run tools/tracker.py mark 0.2 05.11 Выполнено      # день: ГГГГ-ММ-ДД, ДД.ММ, ДД.ММ.ГГГГ, today
uv run tools/tracker.py mark 3.2 06.11-09.11 "В работе"   # диапазон дат; статус «-» убирает факт
uv run tools/tracker.py log --item 0.2 --what "Готов tracker.py" --who "Sonnet 5.5 / high" \
       --commit abc1234 --rounds 1 --tokens 120000 --link https://...
uv run tools/tracker.py review --item 0.2 --round 1 --severity существенное \
       --text "Суть" --repro "Как воспроизвести" --by "Sonnet 5.5 / high"
uv run tools/tracker.py review-status R-0.2-1 исправлено --comment "Исправлено в abc1234"
uv run tools/tracker.py decision Р-1 --answer "Apache-2.0"
uv run tools/tracker.py gh-sync --dry-run            # план зеркала в GitHub, ничего не меняя
uv run tools/tracker.py gh-sync                      # создать/обновить Issues и карточки доски
```

Статусы: «План», «В работе», «Выполнено», «Доработка», «Ждёт решения».
Серьёзность замечаний: блокирующее, существенное, незначительное, предложение.
Статусы замечаний: открыто, исправлено, отложено, отклонено.

Общие опции: `--yaml ПУТЬ` и `--out ПУТЬ` (или переменные `TRACKER_YAML`, `TRACKER_XLSX`) — работать
с другими файлами, например для проб; `--today ГГГГ-ММ-ДД` — считать «сегодня» этой датой. Без неё «сегодня» — дата по Москве (UTC+3),
какой бы пояс ни стоял на машине.
Команды, меняющие YAML, сразу пересобирают Excel; `--no-build` — только записать YAML.
Коды выхода: 0 — успех, 1 — ошибка данных, аргументов или `gh`, 2 — Excel-файл занят.

## Формат и график

- Формат YAML описан комментариями в начале `tracker.yaml`: `start_date` и `grid_end` (сетка — каждый день),
  `calendar.marks`, `people`, `github`, пункты `items` с полями `person`, `plan`, `fact`, `issue`.
- **Клетка дня:** есть факт — он (`fact` — это `{дата: статус}`); иначе день внутри плана — «План»; иначе пусто.
  Текущий статус пункта — последний по дате факт, иначе «План».
- **Строка этапа** показывает статус подэтапов дня: «Ждёт решения» > «Доработка» > «В работе» >
  «Выполнено» (когда все активные подэтапы дня выполнены) > «План». Сроки этапа — из подэтапов.
- **Срок** пункта — `plan.end`. В колонке «Срок» он красный, если срок прошёл, а пункт не «Выполнено».
- Дни из `calendar.marks` подсвечены, текст отметки — в примечании к клетке с датой в шапке (и на листе «Легенда»).
  Сегодняшний день (на момент сборки) обведён красной рамкой.
- Сетка сама растёт, если план или факт выходят за `grid_end`. Листы Excel: «График», «Сроки», «История»,
  «Ревью», «Решения», «Легенда» (и скрытый `_snapshot`). Печать: «График» — A3 альбом, 1 страница в ширину;
  остальные листы — A4 альбом.
- `load → save` не меняет файл (заголовок, порядок ключей, даты сохраняются побайтно). Неизвестные ключи
  верхнего уровня сохраняются, но пишутся в строчной форме `ключ: {…}`. Комментарии внутри данных не
  сохраняются — заметки пишите в поле `comment`.

## `due` — начало сессии

Печатает группы «Просрочено», «Сегодня», «Завтра», «Ближайшие N дней» (по умолчанию 3, `--days N`). В список попадают
пункты (не этапы) с `plan.end`, у которых последний факт не «Выполнено». Строка:
`<№> <название> — срок ДД.ММ, участник <…>, статус <…>`. Ниже, в тех же группах, идут развилки Р-x
без ответа (`decisions`) со сроком в окне или уже прошедшим: `Р-1 <вопрос> — срок ДД.ММ, развилка без ответа`.
`--person Б` оставляет пункты, где Б есть среди участников («Б, В» подходит); развилки показываются
без фильтра или при `--person А` (капитан — первый в `people`). Код выхода всегда 0.

## `gh-sync` — зеркало в GitHub

Односторонне: YAML → GitHub. Правки на доске и в Issues не возвращаются, при следующем запуске они
перезапишутся. Настройки берутся из раздела `github` (`owner`, `repo`, `project_title`).

1. Находит доску Projects (v2) владельца по названию или создаёт её; создаёт недостающие поля:
   Status (План, В работе, Доработка, Ждёт решения, Выполнено), «Участник», «Начало», «Срок», «Этап».
   Если Status уже есть (стандартное поле новой доски), его варианты заменяются на нужные через GraphQL.
2. Для каждого пункта (кроме этапов): нет `issue` — создаёт Issue `[<№>] <название>` с телом (участник,
   исполнитель, ревью, план, комментарий, пометка «зеркало tracker.yaml…») и метками `этап-<N>`,
   `участник-<буква>` (метки создаются при необходимости) и **сразу** записывает номер в `issue`
   (перечитав YAML и тронув только это поле, так что параллельные `mark`/`log` не теряются); есть — обновляет
   заголовок, тело и метки (устаревшие `этап-*` / `участник-*` снимаются). Issue закрывается при статусе «Выполнено» и открывается снова,
   если статус сменился. Если номера нет, но на GitHub есть Issue с заголовком `[<№>] …`, он привязывается.
3. Добавляет Issue на доску и выставляет поля. Текущие значения полей карточек читаются через
   `gh api graphql` и сопоставляются по id поля: в выводе `gh project item-list --format json`
   ключи полей с кириллическим именем приходят с испорченным первым символом.

Команда идемпотентна: состояние читается через `gh … --json` и сверяется с YAML; без изменений в YAML
повторный запуск не вызывает ни одной мутирующей команды. `--dry-run` читает состояние и печатает план без
записи (только читающие вызовы `gh`; если репозитория или доски ещё нет, план — «всё создать»).
Мутирующие вызовы при лимите GitHub (HTTP 403/429, secondary rate limit) повторяются один раз после паузы 7 с.
При ошибке `gh` (и при Ctrl+C) печатается сообщение, код выхода 1, а номера Issue, уже записанные в YAML,
остаются; повторный запуск продолжает с места остановки.

## Заметки пользователя и синхронизация с Excel

- Можно писать прямо в Excel: колонка «Комментарий» листа «График» и колонки «Решение пользователя» /
  «Дата решения» листа «Решения».
  - Перед **любой** записью Excel (build и все команды, меняющие YAML) скрипт сам считывает эти ячейки
    в YAML (sync). Заметка не потеряется, даже если забыть запустить `sync`.
  - Чтобы отличить правку пользователя от устаревшего текста, в Excel лежит скрытый лист `_snapshot`
    (то, что скрипт записал в эти ячейки). В YAML попадает только то, что вы изменили в Excel; правка в YAML,
    сделанная после сборки, не затирается старым текстом из Excel.
  - Если одну заметку изменили и в YAML, и в Excel, сохраняются обе: `текст YAML | Excel: текст Excel`,
    выводится предупреждение.
  - Очистка ячейки в Excel стирает заметку в YAML. Если ответ на развилку изменён, а дата нет,
    ставится сегодняшняя дата.
- **Файл занят:** если Excel открыт (есть `~$…`) или файл держит OneDrive, Excel не перезаписывается,
  команда печатает сообщение и завершается кодом 2. Изменения команд `add/mark/log/…` при этом уже
  записаны в YAML; закройте файл и запустите `build`.
- Строки, добавленные в Excel вручную, при пересборке исчезают (sync предупредит); новые пункты — командой `add`.

## Тесты

```
uv run --no-project --with pytest --with pyyaml --with openpyxl python -m pytest tools/tests -q
```

Образец данных — замороженная копия `tools/tests/fixtures/tracker.yaml`; её не правят (ожидания тестов зашиты в
неё). Живой `docs/tracker/tracker.yaml` читается только в тестах «заголовок = `DEFAULT_HEADER`» и «побайтный
проход». Команды работают на копиях во временной папке, `gh` подменяется (`subprocess.run`), сеть не нужна.

Стиль: `uvx ruff check tools` и `uvx ruff format --check tools` (настройки — `ruff.toml` в корне штаба).
