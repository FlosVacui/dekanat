## Оценка пунктов, названных исполнителем этапа Б
1. **Шкала баллов — приемлемо, формулировку комментария исправить (R-3.3-2).** Сверено с набором (`app/db/seed-data.ts:190-198, 301-309`): у экзамена без итога число — баллы за семестр (Микроэкономика 41, Корпоративные финансы 22), «из 60» верно. У закрытого экзамена число — сумма: Статистика 79 → «4» (70–84), Линейная алгебра 92 → «5», Информатика 87 → «5»; «из 100» верно. У долга Эконометрика 41 → «2» (меньше 50), в комментарии набора 32 + 9; «из 100» верно. У зачётов набор даёт 38, 44, 46, 61 при итоге «впереди» и 72, 88 при «зачтено»: 61 больше 60, значит шкала зачёта — не «60 за семестр», и «из 100» согласуется с черновиком данных. Экран не обещает лишнего: у зачёта и закрытой дисциплины отметки допуска нет, подпись Э-5 говорит «Всего баллов, семестр и экзамен» только у закрытого экзамена.
2. **Сданные без даты в «Прошедших» — размещение верно, подпись «Дата не назначена» нет (R-3.3-4).**
3. **Пересдача как ближайший контроль — приемлемо.** Видна на снимке («Ближайшая пересдача — 18 ноября»), слово «пересдача» названо на карточке, в «Сессии» и в фразе; логика в `nearestControl`, проверена тестом `ближайший контроль` и 14 днями. Остаётся пограничный случай прошедшей пересдачи (R-3.3-5).
4. **Слово «семестр» не пишется в карточках — приемлемо, не замечание.** Задание требует «N из 60 баллов» без слова «семестр»; к нему текст не подогнан, а совпал. Ограничение: `m0.spec.ts` ищет ссылку «Семестр» без `exact`, любая будущая карточка со словом «семестр» в тексте сломает его. Назван риск, не замечание. Свои тесты исполнитель пишет с `exact: true`.
5. **«Итог: <плашка>» сохранён — приемлемо.** `m0.spec.ts` не менялся (`git diff main...HEAD -- app/tests` показывает изменённым один `screenshots.ts`); он зелёный.
6. **`screenshots.ts` — верно.** Без `SCREENSHOT_ONLY` переменная `only` равна `null` и обе функции снимка (`shoot`, `shootCurrent`) не пропускают ничего: снимаются все экраны, как раньше. Папка по умолчанию — `<дата>-3.3`; прежние `2026-11-11-2.4`, `2026-11-13-3.4`, `2026-11-14-3.2`, `2026-11-14-imp-020-1` в диффе не тронуты (в диффе PNG только восемь новых файлов в `2026-11-14-3.3`). Повторный запуск в тот же день перезапишет только папку `<дата>-3.3`. Сам снимочный прогон `npm run screenshots` я не запускал.

**Что живые данные не показывают — оценка.** Все четыре перечисленных случая действительно не видны ни в какой день, потому что сроки набора не меньше Д+2. Три покрыты модульными тестами (`ближайший зачёт` — grades-screen.test.ts:94; `Прошедшие` у работ — splitWorks, 195-220; `Дата не назначена` — groupSession, 223-239). Пустое «Дисциплин пока нет» ни одним тестом не проверено (`page.tsx:28`): подтверждаю, это пробел, но он в состоянии, которое исполнитель назвал сам; состояние простое и повторяет `EmptyState`, который виден на экране с долгом («Работ пока нет», снимок и тест).
