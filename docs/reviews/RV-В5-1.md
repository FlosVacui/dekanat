## Что проверено и в порядке

**Ветка 1, даты сессии.**
- Дата календаря и сдвиг разведены типом `ControlSpec` (`{ dayOffset; date?: never } | { date; dayOffset?: never }`). `controlBaseDate` берёт дату как есть или `addDays(today, dayOffset)`. Других читателей `exam.dayOffset` в `app/` нет: `grep` даёт только `seed-plan.ts` и `tests/unit/fixtures.ts`.
- Порядок контроля: сортировка по заданному дню (`controlBaseDate`) строкой ISO, это верно для дат вида ГГГГ-ММ-ДД. Условие `base < last ? last : base`, перенос с воскресенья и занятого дня работают на смеси сдвига и календаря. Все постоянные даты (22, 23, 24, 25, 26, 29, 30.12; 13, 14.01) падают не на воскресенье и не повторяются в группе: сверено по календарю (Д = 17.11, вторник; 22.12 — вторник; 13.01 — среда).
- Резервные наборы: `buildReserveCohort` (`seed-reserve-lib.ts:128`) копирует набор через `structuredClone` и `mapStrings` и заменяет только названия групп, факультетов, ФИО и логины; даты контроля у резервов те же, названия дисциплин те же, коллизий нет (`used` считается по группе).
- Порядок «ближайший» на экране успеваемости не изменился: у группы 1 — логистика 23.12, английский 25.12, микроэкономика 29.12, корпоративные финансы 13.01; у группы 2 — Python 22.12, графика 24.12, проект 26.12, матанализ 30.12, физика 14.01. Тесты `grades-data.test.ts:90` и `grades.spec.ts:453` строят ожидание по плану, а не по числам.
- Тесты. Без базы на ветке: `seed-plan.test.ts` — 180 passed (конфиг vitest без `globalSetup`, `app/` распакован в `/tmp`). Новый тест `AROUND_JURY` проверяет заявленное: на старом `seed-data.ts` из `main` он краснеет в 18 случаях (все Д с 14.11 по 04.12, кроме 21–23.11 — там старые даты случайно годились), на новом — зелёный.
