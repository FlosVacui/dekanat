# Правила разработки

Общий порядок работы — в [CLAUDE.md](CLAUDE.md) и [docs/PROCESS.md](docs/PROCESS.md), план — в [docs/ROADMAP.md](docs/ROADMAP.md). Здесь — правила для веток, коммитов и кода. Репозиторий один: продукт и документы процесса лежат вместе ([Р-1](docs/DECISIONS.md#р-1-репозитории)).

## Ветки и PR
- `main` всегда зелёный: проверки проходят, прототип запускается по README.
- Работа идёт в ветках `<тип>/<пакет>-<кратко>`, тип — `feat`, `fix` или `docs`. Примеры: `feat/3.2-schedule`, `docs/1.4-stack`.
- Один набор файлов правит один исполнитель. Зоны файлов — в [docs/PROCESS.md](docs/PROCESS.md#люди-и-зоны).
- Пока удалённого репозитория нет, смена коммитит в локальный `main`. Ветки и PR начинаются с первого push ([пакет 0.4](docs/ROADMAP.md)).
- В `main` ветка попадает через PR: зелёный CI, ревью, squash. История линейная.
- Перед PR — локальная проверка одной командой: `uv run tools/check_all.py`.
- Слияние — командой `gh pr merge <N> --squash --author-email <служебный адрес GitHub>`. Кнопка на сайте GitHub подписывает коммит основной почтой аккаунта, а репозиторий станет публичным.
- Исключение из правила «всё через PR» — коммиты учёта `chore(tracker): …` (`docs/tracker/tracker.yaml`) прямо в `main` после `git pull --rebase`.

## Коммиты — Conventional Commits
```
<тип>(<область>): <что сделано, по-русски>

<зачем; ссылки: пакет 3.2, ТР-9.1, R-3.2-1, ADR-0002>
```
- Типы: `feat`, `fix`, `docs`, `test`, `refactor`, `perf`, `build`, `ci`, `chore`.
- Если коммит закрывает замечание ревью или требование матрицы, его номер указывается в теле.

## Код
- Скрипты в `tools/` — Python через uv; зависимости записаны в самом скрипте. Системный Python не нужен.
- Файлы и вывод — UTF-8. Пути с кириллицей и пробелами — норма.
- Комментарии — по-русски, кратко, о том, почему, а не что.
- Новая функция приходит с тестами. Исправление ошибки — сначала тест, который её воспроизводит.

## Секреты и данные
- Ключи и пароли сервисов — только в `.env`, которого нет в git; образец — `.env.example` без значений.
- gitleaks и `tools/check_clean.py` стоят в pre-commit и в CI. Перед открытием репозитория проверяется вся история.
- В репозиторий не попадают: персональные данные, личные пути, адреса почты, материалы других проектов.
- В прототипе только вымышленные данные.

## Пути
Внутри репозитория пути пишутся через `/` (`docs/ROADMAP.md`).
