# /handoff — точка сохранения

Цель: следующий разработчик продолжает работу по одному репозиторию, без этого чата. Выполни шаги по порядку. Коммитов два: сначала работа, потом записи о ней — запись не может содержать хеш собственного коммита.

1. **Проверки.** `uv run tools/check_all.py`. Красный шаг исправь или опиши в `HANDOFF.md`, раздел «Что сломано или под сомнением». Красное не замалчивается.
2. **Материалы смены** — допиши, если ещё не записано:
   - новый итоговый промпт или задание — строка в `prompts/INDEX.md`;
   - ошибка ИИ — `docs/evidence/ai-errors.md`;
   - новый инструмент — `docs/evidence/tools.md`;
   - ручной шаг — `docs/evidence/manual.md`.
   Пишется только то, что было. Не было ошибок — так и пиши.
3. **Коммит работы.** Проверь `git status`: в коммит не попадают `.env`, личные файлы и постороннее. Сообщение — Conventional Commits по-русски. Запомни хеш: `git rev-parse --short HEAD`.
4. **Лимиты.** Сними `get_usage`, если инструмент есть. Нет — попроси разработчика набрать `/usage`. Нет и этого — пиши «не снято». Числа не придумывай.
5. **Журнал.** Новая запись сверху в `docs/history/JOURNAL.md` по шаблону `docs/templates/journal-entry.md`. Хеш — из шага 3. Числа лимитов — из снимков начала и конца смены. Токены субагентов — из итогов их вызовов.
6. **Учёт.** Статусы: «План», «В работе», «Выполнено», «Доработка», «Ждёт решения». «Выполнено» ставится только после приёмки и ревью.
   - `uv run tools/tracker.py mark <№> today "<статус>"` — для каждого затронутого пакета;
   - `uv run tools/tracker.py log --item <№> --what "…" --who "…" --commit <хеш> --tokens N`;
   - замечания ревью этой смены — `uv run tools/tracker.py review …`; решённые — `review-status …`.
7. **HANDOFF.** Перепиши `docs/HANDOFF.md` целиком по шаблону `docs/templates/handoff.md`.
8. **Промпт для следующей сессии.** Новый файл `prompts/handoff/H-NNN.md`, номер — следующий по порядку. Промпт самодостаточный: кто ты, что прочитать, что сделать по порядку, чего не делать без подтверждения, чем закончить. Добавь строку в `prompts/INDEX.md`.
9. **Второй коммит.** Учёт — отдельно: `chore(tracker): …`. Журнал, HANDOFF и промпт — `docs(handoff): …`.
10. **Push.** Удалённый репозиторий есть — push ветки. Создание репозитория, первый push и смена доступа — только после подтверждения человека.
11. **Ответ разработчику:** что сделано, что не закончено, какие вопросы ждут его, снимок лимитов и текст промпта целиком — под копирование.

Подробно — `docs/PROCESS.md`, раздел «Смены».
