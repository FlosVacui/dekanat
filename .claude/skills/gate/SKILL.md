# /gate — ворота этапа

Аргумент — номер ворот: `/gate 1`. Без аргумента — ближайшие по `docs/ROADMAP.md`, раздел 6. Ворота закрывает пользователь, а не ты: твоя работа — собрать ему картину без прикрас.

1. **Проверки.** `uv run tools/check_all.py`. Красное — блокирует ворота.
2. **Пакеты этапа.** Для каждого пакета из таблицы этапа в `docs/ROADMAP.md`: выполнен ли критерий «Готово, когда» и чем это доказано — тест, отчёт, снимок, коммит. Нет доказательства — пакет не готов.
3. **Матрица требований.** В `docs/REQUIREMENTS.md` заполни «Доказательство» у требований этого этапа. Пустая клетка у требования, которое этап должен был закрыть, — замечание.
4. **План против факта.** Сроки — `uv run tools/tracker.py due`. Расход лимитов — строки «Токены» журнала против бюджета этапа из `docs/ROADMAP.md`, раздел 8. Как считать долю этапа, ещё не определено (`docs/ISSUES.md`, IMP-009): пока приведи числа из журнала как есть и напиши «сверить с бюджетом нечем». Базу для сравнения не придумывай.
5. **Оценки ролей** — запусти те, что положены этим воротам. Модель и effort — явно, как в `docs/PROCESS.md`, раздел «Роли». Не больше двух субагентов одновременно: сначала проверяющие (`security-auditor`, `mobile-qa`, `fact-checker`), после их отчётов — `jury`. «Жюри» оценивает то, что есть на момент запуска; если находки проверяющих ещё не исправлены, скажи об этом в итоге.
   - Веха М0 (ворота 2): `mobile-qa`; базовые тесты `security-auditor`.
   - Веха М1 (ворота 3): `security-auditor`, `mobile-qa`, `jury`.
   - Ворота 4: второй аудит `security-auditor`.
   - Ворота 5: `fact-checker` по описанию и README, финальный `security-auditor`, `jury` с effort xhigh.
6. **Риски.** Пройди `docs/risks.md`: что сработало, что изменилось, что добавить.
7. **Развилки.** Из `docs/DECISIONS.md` — те, чей срок на этих воротах. По каждой: варианты, твоя рекомендация, что будет без ответа.
8. **Отставание.** Этап не укладывается — предложи сокращение по списку `docs/ROADMAP.md`, раздел 7, в том порядке. То, что там названо «не сокращаем», не сокращается.
9. **Итог пользователю:** таблица пакетов (готов или нет и чем доказано), блокирующие замечания, план против факта, развилки, твоя рекомендация: закрывать ворота или нет.
10. **Запись.** Решения пользователя — в `docs/DECISIONS.md` и `uv run tools/tracker.py decision Р-x --answer "…"`. Итог ворот — в запись журнала смены.

Блокирующее замечание ворота не проходят. Оценки ролей записываются как есть, низкие тоже.
